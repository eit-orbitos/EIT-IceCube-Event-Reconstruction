# Data provenance and external-data boundary

## Included data

`examples/reference_results.json` is generated by the **local, fully synthetic** `eit_icecube.simulator` code with the fixed configuration. No IceCube Collaboration data or copyrighted article text are included, downloaded, mirrored or redistributed.

- Synthetic hit input: `event_id`, hit `sensor_id,x_m,y_m,z_m,t_ns,charge_au`.
- Synthetic target (separately exported only by the generator): `event_id,scenario,direction_xyz,outlier_sensor_ids,observed_hit_count`.
- All data use predeclared pseudo-random seeds in the config and no model parameters are fitted from benchmark labels.

## Real sources to consider later

1. **IceCube Data Releases**: https://icecube.wisc.edu/science/data-releases/ — official catalogue; use source-specific data policies and citation instructions.
2. **IceTracks-DR2**: https://doi.org/10.7910/DVN/MMIIZA — includes already-reconstructed track-like event candidates from 2008–2022, not raw DOM-pulse arrays required for reconstruction from sensor times; it cannot directly validate a raw-hit reconstruction pipeline.
3. **Historical IceCube Public Data Project / ODF**: https://icecube.umd.edu/PublicData/ — describes records `q,t,x,y,z` and access to a small fraction of pulse-level samples; the actual file availability, geometry, calibration, usable labels, license, timing epoch, and quality cuts must be separately reviewed before scientific use.

The optional `reconstruct-csv` command accepts a **preprocessed** one-event CSV with `q,t,x,y,z` *or* equivalent canonical columns; it does not read the ODF binary format, parse I3, apply ice models, decode trigger context or infer truth. Its result is forcibly labeled scientifically unvalidated. In particular, feeding real data to a toy planar model does not make its resulting direction or brightness a valid IceCube measurement.
